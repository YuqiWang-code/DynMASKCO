# 服务器连接与同步 Skill

## 目的

使用项目根目录 `.vscode/sftp.json` 中的服务器配置，执行 SSH 只读巡检、项目同步预览/同步和环境记录。该 skill 仅服务于本项目，不把密码复制到 skill、文档、命令行日志或提交中。

## 用户授权范围

用户已明确授权本项目后续在当前请求范围内执行以下服务器相关操作，但每次具体执行仍需记录目标和结果：

- 读取 `.vscode/sftp.json` 并使用其中的 SSH/SFTP 配置连接服务器；
- 通过 SSH 执行服务器状态、项目、进程、日志、GPU、Python/Conda/venv 和磁盘巡检；
- 将当前本地项目按排除规则同步到配置中的远端项目目录；
- 在远端已确认的项目环境中启动、监控和停止本项目训练任务；
- 获取训练日志、指标、配置、checkpoint 和其他用户要求的训练结果，并下载到本地指定目录；
- 为训练、同步和结果获取创建或更新 `docs/temporary/` 中的报告和索引；
- 必要时创建远端实验目录、日志目录和结果目录。

该授权不包括以下默认行为：

- 不得泄露密码、私钥、令牌或其他秘密；
- 不得向无关主机或路径传输项目；
- 不得无记录地覆盖已有 checkpoint、结果或日志；
- 不得删除远端项目、结果、权重或日志；
- 不得修改系统服务、提权、修改防火墙或安装系统级软件；
- 不得因一次训练授权而自动启动其他实验；每个实验仍须记录命令、环境、输出和终态。

用户如在后续具体请求中明确要求覆盖、删除、清理、重跑或修改环境，则以该具体请求为准，并在执行前记录受影响的远端路径和对象。

2. SSH 探索优先使用 Paramiko 的内存认证，避免把密码放入 shell 参数、脚本文件或进程列表。
3. 服务器信息巡检默认只读：主机名、内核、CPU、内存、磁盘、GPU、Python、conda/venv、项目目录、Git 状态和文件清单。
4. 同步属于远端写操作。同步前先计算本地清单并排除 `.git`、缓存、结果、权重、密钥和 `.vscode`；确认目标目录后再上传。
5. 不删除远端文件，不覆盖远端结果/权重，不执行提权、服务重启或改变环境的命令，除非用户在当前请求中明确授权。
6. 报告中只记录主机、路径、版本、环境名和数量等非秘密信息；绝不记录密码、私钥内容、令牌或完整敏感配置。

## 推荐流程

### 1. 读取配置

从 `.vscode/sftp.json` 读取 `host`、`port`、`username`、`remotePath`。密码只在内存中传给 Paramiko；如果认证失败，停止并报告，不反复尝试。

### 2. 只读服务器巡检

使用单次 SSH exec 执行以下只读命令并采集 stdout/stderr/退出码：

- `hostname && uname -a && uptime`
- `nproc && free -h && df -h`
- `python --version; which python`
- `conda env list`（若存在）
- `python -m pip list`（当前解释器）
- `nvidia-smi`（若存在）
- `pwd; ls -la; find <remotePath> -maxdepth 2 -type d`
- `git -C <remotePath> status --short` 和当前分支/提交（若为 Git 仓库）

对远端项目仅读取目录和文本元数据；不要上传前先执行项目代码。

### 3. 本地同步

本地同步源是当前仓库根目录，目标是配置中的 `remotePath`。默认排除：

- `.git/`
- `.claude/`
- `.cursor/`
- `.vscode/`
- `__pycache__/`、`*.pyc`
- `saved_models/`、`results/`
- 密钥、凭证、临时日志和系统文件

同步前生成文件数、总大小、删除/覆盖/新增清单；远端已有文件不在排除清单中时，先比较哈希或大小/时间。使用 SFTP/Paramiko 分批上传，保持目录结构，不执行远端删除。同步后重新读取远端清单并记录验证结果。

### 4. 远端训练与结果获取

用户明确授权后，可以通过 SSH 在服务器上启动训练、查看进程和日志，并把训练结果安全取回本地。训练和结果获取属于远端写入/计算操作，每次执行前都要向用户说明目标环境、入口命令、输出目录、预计资源和停止条件；不得因为上一次授权而默认启动下一次训练。

### 4.1 启动前检查

1. 重新读取 `.vscode/sftp.json`，确认目标主机、远端项目目录和认证方式。
2. 确认同步已经完成，或明确记录远端使用的代码提交/文件清单；不要在未同步当前代码时启动训练。
3. 确认使用的 Python 环境。优先使用报告中已验证的项目环境（例如 `MASKCO_env` 或 `ZH`），先执行 `python --version`、`python -c 'import jax, flax, numpy'` 和必要的 GPU 可见性检查。
4. 检查磁盘、GPU、已有训练进程、目标输出目录和同名实验，避免覆盖已有 checkpoint、日志或结果。
5. 训练命令必须使用绝对或明确的远端路径，设置非交互环境，并把 stdout/stderr 写入新的、带时间或实验名的日志目录。

### 4.2 启动方式

- 优先使用 `nohup` 或 `tmux`/`screen`，确保 SSH 断开后训练继续运行；长任务不得依赖当前交互 shell。
- 每次任务必须保存：实验名、代码版本、环境名、完整命令、启动时间、GPU、输出目录和日志路径。
- 推荐命令形态：

  ```bash
  cd <remote_project>
  source <conda-or-venv-init>
  conda activate <environment>
  nohup python <entrypoint> <args> > <log_dir>/<experiment>.log 2>&1 &
  echo $!
  ```

- 不在命令行中传递密码、私钥、令牌或其他秘密；不把秘密写入实验参数、日志或报告。
- 不使用 `kill -9`、删除输出目录、覆盖已有 checkpoint 或修改系统/环境；如需停止、清理或覆盖，必须单独获得当前请求的明确授权。

### 4.3 监控与故障处理

使用 SSH 只读命令定期获取：

- 进程状态：`ps`、`pgrep`、`nvidia-smi`；
- 日志尾部和错误模式：`tail`、`grep`；
- 输出目录、checkpoint 和结果文件的名称、大小、修改时间；
- GPU 利用率、显存、温度、训练速度和最近 epoch/step。

监控必须覆盖成功和失败终态，包括正常完成、异常退出、OOM、CUDA/JAX 错误、磁盘不足、挂起和被系统终止。发现异常时先停止自动重试，保存错误摘要并报告，不擅自更改超参数或切换环境重跑。避免高频轮询；长任务通常每 30–300 秒检查一次即可。

### 4.4 获取训练结果

1. 先列出远端输出目录并核对实验名、checkpoint、日志和结果文件，避免下载未完成或仍在写入的文件。
2. 对文件读取大小、修改时间和必要时 SHA-256；对 checkpoint 先确认训练进程已结束或文件已稳定。
3. 只下载用户需要的结果：日志摘要、指标 JSON/CSV、最终 checkpoint、配置和可复现元数据。不要默认下载整个服务器项目、缓存或所有历史权重。
4. 下载到本地 `docs/temporary/` 或用户指定目录；大型 checkpoint 下载前说明大小、预计耗时和本地磁盘需求。
5. 下载后在本地核对文件大小/哈希，生成结果索引，注明来源主机、远端路径、实验名、代码版本、环境和下载时间。若结果来自旧代码或未提交工作区，必须明确标记。
6. 不删除远端结果；若需要归档、清理或移动，先获得单独授权。

### 4.5 训练报告

每次训练或结果获取都应更新 `docs/temporary/` 下的实验报告，至少包括：

- 远端主机和项目路径（不含密码）；
- 代码版本或同步清单；
- Python/Conda 环境；
- 完整训练入口和参数（过滤秘密）；
- PID、日志和输出目录；
- 资源使用、开始/结束时间和最终状态；
- checkpoint/指标文件清单、大小和哈希；
- 错误、重试、未完成项和下一步建议。
## GitHub 推送

用户明确要求推送时，可通过现有 Git remote 推送本地工作区，但推送会公开发布仓库内容，必须先检查推送目标和发布范围。

1. 核对 `git remote -v`、当前分支、工作区状态和待推送提交；不得输出或改写嵌在 remote URL 中的凭证。
2. 检查所有新增/修改文件，确认没有服务器密码、私钥、令牌、`.env`、训练产物、模型权重或不应公开的数据。
3. 不自动执行 `git add -A`、创建提交、改写历史、强推或推送到陌生 remote。若用户只说“推送”，先说明目标仓库/分支和将包含的改动；缺少提交时先准备差异或请用户明确是否需要提交。
4. 推送前再次确认待发布提交范围及目标分支；使用普通 `git push <remote> <branch>`，不得加 `--force`。
5. 推送失败时如实报告；认证、权限或安全策略阻止时，不得改用其他凭证或路径绕过。

## 禁止事项

- 禁止把明文密码写入此 skill 或报告；
- 禁止使用 `ssh user@host '...'` 搭配密码出现在命令行；
- 禁止 `rm -rf` 远端路径；
- 禁止把本地 `.git`、结果、权重、密钥和凭证同步到服务器；
- 禁止将动态研究目录重新作为当前项目入口。
