**判定：`PD-CLOSED`**（按总纲 §4 止损：修正后仍 < +0.5%，且三档同号）。
**可写进论文的一句**：在这个评测器里，**把距离项放进接单价值会稳定损害效用**——
因为真实里程的边际量由派车（车已在路上、路线共享）决定，不是订单的欧氏往返；
用订单级距离做价值，等于给"远单"加了一个**只存在于代理里的成本**。
这同时解释了为什么 `marginal` 对最强基线是 **−0.19%**：它也是距离感知族。

## 2. 下一支线预登记：`M2` 车队规模—发车时刻联合决策（新机制类）

**为什么是它**：已测机制全在
(a) 密度阈值族（已榨干 +0.27%）与
(b) 路线内顺序/趟数族（三条精确零 + 结构性阻塞）。
`M2` 不属于任何一族：它改的是**派多少车、什么时候派**，目标是压低那 **32% 固定开销** 的生成量。
GPU 与外部求解器都没碰过这一层。

**机制（最小实现）**：新增 `FleetDispatchReplanner(SaaReplanner)`：

```
在 plan() 里，取父类给出的 plan 后：
  if 当前在途车数 >= m(clock) 且该车尚无 committed 客户：
        清空该车 mutable_suffix（不发车）
  m(clock) = 1 if clock < 4 else 2 if clock < 8 else 3 if clock < 12 else 4
```

* 车辆一旦回仓即可再次被派出（与控制臂同语义），**只是限制同时在途的数量**；
* 不改接单判据、不改路线层、不改协议；纯粹是**派车节奏**。

**判据（预登记，跑前冻结）**：

| 项 | 要求 |
|---|---|
| 主判据 | 5 天均值 ≥ 静态 λ ×1.005 |
| 机制判据（关键） | **总车时（Σ 在车时长）必须比 control 下降 ≥5%**；若车时不降，机制无效，即使效用偶然为正也记 `VOID` |
| 安全 | 0 次承诺违规 / 0 次预算违规 / `hard_feasible` 全 True |
| 止损 | 两轮内主判据为负 ⇒ 关闭；`VOID` 即关闭 |

**预言（可被推翻）**：车时会降 8%–20%，但因为控制臂本来只用 4/15 车、账已经接近最优，
**净效用大概在 −1% ~ +1%**；若 > +1.5% 则说明 32% 开销真的有可压空间，那将是本项目第一个结构级正结果。
