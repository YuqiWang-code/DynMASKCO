## 3. 判定（按预登记 §3，不动判据）

`Δ(DP − 控制) = −63.21 ≤ 0` ⇒ **`DOMINATED`**。

附加条件也全部不满足：`Δ(DP − 静态)` = 1745.32 − 1828.65 = **−83.33**；正日数 1/5。

## 4. 这是本轮最干净的一个负结果

D4 v3 里 DP 是 **+1.45%（5/5 天全胜）**；到了全仿真变成 **−3.5%（1/5 天为正）**。
不是"幅度缩水"，是**符号翻转**。差异只可能来自 D4 v3 的简化设定缺了什么：

| D4 v3（表级） | 全仿真 |
|---|---|
| 状态 = 剩余预算 × 剩余单数 | 状态 + 车队、路径、时间窗、派车时机 |
| 接受一个订单只消耗预算 | 接受还改变路线、占用车辆、影响后续可插入性 |
| 收入 − 燃油 − 品质 | 同上，但**可行性**是硬门（TW / 容量 / 期限） |

⇒ **表级 DP 学到的是"预算分配"的最优，而真实瓶颈是"可行性分配"。** 预算用得更省（energy 665.6 < 707.0）
但服务单数没涨（107.0 vs 107.6）、距离反而更长（526.8 vs 514.7 km）——
即 DP 省下了预算却**买不到**任何东西，同时把路线搞差了。

这与 [PANEL-TIER](2026-10-18_PANEL_TIER_执行记录.md) 的结论互相印证：被拒订单释放出的资源
**不能**被后续订单有效利用（可行性已经不在那里了）。

## 5. 这不能证明什么

- 5 天、单 GATE 集、单 seed。`DOMINATED` 的强度是"这一族在冻结 a1 协议下的这一设定里不迁移"，不是"状态依赖无用"。
- 值表来自 D4 v3 的简化状态空间；换成含车队/时间窗的状态可能不同——但那就不是本实验测的东西。
- 不排除实现层面的次优（DP 的 `n_expected=193` 用 TRAIN 期望单数做剩余步数代理）。这一点已在 [INV-2](2026-10-18_INV2_DP反演执行记录.md) 记录为已知近似。
- 本记录**不**改写 D4 v3 的 +1.45%，那是表级事实；两份记录并存，口径不同，不得混读。
