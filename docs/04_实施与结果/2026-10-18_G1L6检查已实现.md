- 代码：`scripts/bench/{cc_dvrp3t_gen.py, verify_no_future.py}`

## 1. 实现

`cc_dvrp3t_gen.py` 三处（commit `419f4cc6` / `9cb257b9`）：

1. `BUDGET_OVERRIDE` / `BUDGET_SOURCE`：预算可外部指定，默认仍自标定但**如实标身份** `self_dataset(PRE_L6_FIX)`；
2. CLI `--budget` / `--budget-source`；
3. `meta['identity_sha256']`：把"数组哈希 + budget + source + burst + slot + seed + rho"一起绑住。
   起因是实测发现 `dataset_sha256` **只覆盖数组**，同数组配不同预算会**撞哈希**：

   ```
   b_o2  B=460.58  src=self_dataset(PRE_L6_FIX)   arr=2cace9da835a  id=dd473890deff
   b_n2  B=440.81  src=R1_CAL                     arr=2cace9da835a  id=5f714e7e0f93
   ```

`verify_no_future.py` 新增 `check_budget_provenance(meta)`（commit `d2b43587`）：

- `budget_source` 缺失或以 `self_dataset` 开头 ⇒ 失败；
- `identity_sha256` 缺失 ⇒ 失败。

## 2. 判别力实测（关键：不是"能跑"，是"能分开"）

| 数据集 | 预算来源 | `verdict` | 失败项 |
|---|---|---|---|
| `b_o2` | 自标定（旧行为） | **FAIL** | `['budget_provenance']` |
| `b_n2` | `R1_CAL`（CAL 标定） | **PASS** | `[]` |

一个检查只有在**能判错**的时候才算检查。这两行就是它的判别力证据。

## 4. 必须写清的边界

1. **L6 只覆盖 `budget_B` 一条**。`cooling_share`、`mean_full_energy` 的其它用法未查；
   L6 作为"类"并未完全封闭，只能说"预算这一条已有可判别的检查"。
2. **已入库六集不会通过新检查**（它们没有 `budget_source`/`identity_sha256`）。按纪律：
   它们的状态记为 `PRE_L6_FIX_BUDGET`，**不重跑**（重跑会改变身份），
   此前所有基于它们的结论保持原样，但**不得**再称其为"干净留出集"。
3. L8 仍未解决。G1 的 8/8 需要 L7 与 L8 都到位，其中 L8 还差环境级重放代码。
4. 本记录**不**主张"G1 接近达成"：6/8 与 8/8 的差别在于 L7（评估路径）恰是最容易被忽略的一类。
