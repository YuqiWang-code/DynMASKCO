# GPU 侧诊断：把 burst 数据送进接拒层仿真 ⇒ **天花板完全不变（+0.27%）**

- 日期：2026-10-18（继续迭代，第 96 轮）
- 类型：**GPU 实验（对照诊断）**，有 `nvidia-smi` 证据
- 代码：`scripts/bench/gpu_admission_batch.py`（未改）
- 数据：新建 `data/bench/R1_BURST_CAL`（30 天 × 200 单，`--burst-rate 0.3 --budget <CAL> --budget-source R1_CAL`）

## 1. 为什么要做

第 95 轮的比例扫描给出 `RATE-POINT`：burst 0.3 让静态 λ 的闭环 Δ% 从 +1.11% 升到 +1.62%，
但 0.1（+0.92%）与 0.5（+0.56%）都更差。

问题：这个"只在 0.3 出现"的效应，是否出现在**接拒层**（信息/背包结构）？
若接拒层天花板随 burst 变化，那效应有信息学解释；若**不变**，则它只能来自路由/派车耦合。

## 2. 数据身份（先确认可复现）

```
python scripts/bench/cc_dvrp3t_gen.py --regime R1 --n 30 --days 30 --n-orders 200 \
    --seed 777 --burst-rate 0.3 --budget 440.81074545145043 --budget-source R1_CAL \
    --out data/bench/R1_BURST_CAL
→ dataset_sha256 前 8 位可查；verify_no_future: verdict PASS, n_failed 0, tie_groups 429
```

注意：**并列组数 429**（非 burst 的 R1_CAL 为 0），说明 burst 真实生效；
预算显式用 CAL 值（`--budget-source R1_CAL`）以通过 L6 检查。

## 3. 结果：与非 burst 数据**逐位相同**

| 数据 | 静态 ρ\* | 静态收入 | 分时段阈值（ES） | 增益 |
|---|---:|---:|---|---:|
| `R1_CAL`（无并列） | 3.00 | 1876.000 | [3.123, 3.057, 2.870] | **+0.27%** |
| **`R1_BURST_CAL`（burst 0.3）** | **3.00** | **1876.000** | **[3.123, 3.057, 2.870]** | **+0.27%** |

**完全一致**（连 ES 收敛到的 ρ 三个分量都相同）。

GPU 证据：

```
nvidia-smi --query-compute-apps ...
308076, /home/hzeng/miniconda3/envs/MASKCO_env/bin/python, 24612 MiB
308076, /home/hzeng/miniconda3/envs/MASKCO_env/bin/python,  508 MiB
jax devices: [CudaDevice(id=0), CudaDevice(id=1)]
```

## 4. 这条诊断说明了什么

1. **burst 不改变接拒层的天花板**：静态最优阈值、最优收入、分时段增益三者都不变。
   原因是接拒层是一个**按密度贪心装包**的结构，与"订单在时间轴上如何聚簇"无关
   （密度与预算占用量都只依赖 (class, q)）。
2. ⇒ 闭环里 burst 0.3 的 +1.62% **不可能**来自"信息/背包结构"，
   只能来自**路由与派车的耦合**：并列到达时一次涌入多单，SAA 的派车/插入顺序被改变，
   而这种改变在 0.3 恰好有利、在 0.1 与 0.5 都不利（正是 `RATE-POINT` 的非单调）。
3. 这条与 [跨车重分配 BLOCKED 的记账耦合结论](2026-10-18_跨车重分配_BLOCKED_记账耦合结论.md) 互相印证：
   **本项目所有 regime 效应都发生在路由/派车层，而不是接拒层。**

## 5. 对写论文的直接用处

可以写一句很强的负面—结构结论：

> 接拒层（阈值族）的**最优值对到达聚簇结构不敏感**（无并列与 burst 0.3 下 ρ\*=3.00、收入 1876.000、增益 +0.27% 逐位相同）；
> 因此任何在闭环上观察到的 regime 效应都必须归因于路由/派车耦合，而不能归因于"信息结构变化"。

## 6. 这不能证明什么

- 只测了 burst 0.3 一个点（0.1 / 0.5 未跑 GPU 对照）；
- 该 GPU 模型只保留能耗预算，无车辆/时间窗/路线耦合，因此它"不变"是**结构性必然**
  （正确解读：它证明的是"变化不可能来自这一层"，不是"信息无关"）；
- 单集单种子；`R1_BURST_CAL` 的预算显式取 CAL 值，故其绝对收入与 `R1_CAL` 可比，
  但两者都是同一种子生成的同一批订单（只是 reveal_time 被量化）——这一点必须在引用时说明。

## 7. 追加（第 99 轮）：**GPU 路径构造器对 burst 也无反应**

同一份 `R1_BURST_CAL`（burst 0.3，tie_groups 429）跑 `gpu_route_batch.py`（day 0，ρ=3.0）：

```
nvidia-smi: 311794, MASKCO_env/bin/python, 24612 MiB + 508 MiB
NN  : dist=277.44 km  unserved=0.00
ES  : dist=260.95 km  unserved=0.00  w=[1.296, -0.018, 0.488]
distance gain vs NN: +16.5 km (-5.94%)
```

与**无并列**数据上的结果**逐位相同**（277.44 → 260.95，−5.94%）。

### 7.1 这说明什么

两个 GPU 层（接拒层天花板、路径构造质量）**都对 burst 不敏感**：

| GPU 层 | 无并列 | burst 0.3 |
|---|---|---|
| 接拒层最优（ρ\*、收入、增益） | 3.00 / 1876.000 / +0.27% | **完全相同** |
| 路径构造（NN → ES） | 277.44 → 260.95（−5.94%） | **完全相同** |

⇒ **burst 0.3 的 +1.62% 既不在接拒层、也不在构造器**，而只出现在**闭环 SAA 的派车/插入耦合**里。
结合 `RATE-POINT`（0.1/0.5 都更差）与两次"外部干预 = 0 / BLOCKED"，
最保守的正确结论是：

> 该效应是**特定仿真耦合下的产物**，不宜作为"问题性质"来叙述；
> 我们把它降级为**单点观察**，并把它作为"regime 参数必须扫描"的方法学例证。

### 7.2 这不能证明什么

- 未测 burst 0.1 / 0.5 的 GPU 对照（只测了 0.3）；
- 构造器模型不含 reveal 顺序（它只吃"接收集合"），所以"不敏感"部分是该模型的结构性必然；
- 不证明闭环效应是"假的"：它是真实存在的仿真结果，只是**不可归因于问题信息结构**。
