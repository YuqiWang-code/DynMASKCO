# G2-a：CC-DVRP-3T 三 regime × 30 天数据集齐全（含泄漏扫描）

- 日期：2026-10-18
- 类型：**资产/Gate 进度**（总纲 §11.1 **G2** 的数据半边）
- 上游：[D1+D6/D7 生成器与定时任务](2026-10-18_D1_D6_D7_生成器与定时任务.md)

## 1. 做了什么

按总纲 §8.1（`CC-DVRP-3T-Bench`）与 `scripts/bench/roles.py` 的 seed 角色划分，在服务器上生成全部
`regime × role` 组合，并对每个数据集跑 **5 项无未来信息泄漏检查**（`scripts/bench/verify_no_future.py --strict`）。

```bash
cd /home/hzeng/project/ZH/MASKCO_v1/C-VRP_Cold-chainVehicleRoutingProblem
python scripts/bench/cc_dvrp3t_gen.py --regime R3  --n 30 --days 30 --n-orders 200 --seed-role CAL  --out data/bench/R3_CAL
python scripts/bench/cc_dvrp3t_gen.py --regime R1c --n 30 --days 30 --n-orders 200 --seed-role CAL  --out data/bench/R1c_CAL
python scripts/bench/cc_dvrp3t_gen.py --regime R3  --n 5  --days 5  --n-orders 200 --seed-role GATE --out data/bench/R3_GATE
python scripts/bench/cc_dvrp3t_gen.py --regime R1  --n 5  --days 5  --n-orders 200 --seed-role GATE --out data/bench/R1_GATE
python scripts/bench/verify_no_future.py --data data/bench/<NAME> --strict --out results/bench/<NAME>_leak.json
```

## 3. 对 Gate 的意义

总纲 **G2** 的判据是"12 条基线全部 smoke 通过；三 regime × 30 天数据齐全"。

- **数据半边：达成。** 3 regime × 30 天 × 200 单 = 18000 单，全部通过 5 项泄漏检查。
- **基线半边：未达成。** 目前只有 HGS-CVRP / PyVRP / OR-Tools 三条非学习基线在 CMT1 上 smoke 过
  （见 [D2b](2026-10-18_D2b_基线克隆与smoke.md)），且**尚未**接入严格在线动态面板。
  12 条清单见总纲 §6.1–§6.3。

## 4. 这不能证明什么

- 泄漏检查通过只说明"特征生成时没有读未来字段"，**不**说明据此训练的策略一定因果（那要看 dispatch 侧白名单）。
- `R1c`/`R3` 的 regime 参数化是**我们自己定义**的，不是文献标准设定；三 regime 之间的差异是否"有科学意义"仍需在论文里论证。
- 数据集通过检查 ≠ 基准可用：四类 oracle、指标表、leaderboard 都还没在这些集上跑出来。
