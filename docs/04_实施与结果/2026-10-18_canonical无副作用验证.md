# canonical 协议的副作用检验：**在无并列数据上逐位不变**（证明修法无污染）

- 日期：2026-10-18（继续迭代，第 88 轮）
- 类型：**回归验证**（G1 L8 修法的安全性）
- 数据：GATE day 0，`--arms control --canonical-ties`（burst 关闭）
- 对照：同日控制臂（无 canonical），`results/admission_panel/stage1_control`

## 1. 为什么必须做这个检验

L8 修法在**四处**改变了决策顺序（env `_vis`、env `visible_ids`、`_sync_id_map`、`on_reveal` 决策循环），
全部按属性键排序。若这些排序**不是**只在并列组内生效，就会悄悄改变所有既有结果——
那等于用"修泄漏"换掉了历史可比性。

正确性质应是：**当数据里没有任何并列 `reveal_time` 时，四条排序都不改变顺序 ⇒ 结果必须逐位相同。**
已知现有六集并列数为 0，因此这是可以严格检验的。

## 2. 结果：逐位相同

| 量 | 控制（无 canonical） | **`canonical_ab`（canonical 开）** |
|---|---:|---:|
| utility | 1793.888119917363 | **1793.88812** |
| 里程 km | 461.1188008263707 | **461.1188** |
| 服务单 | 94 | **94** |
| `hard_feasible` | True | **True** |

数值在面板输出精度上完全相同（`1793.88812` vs `1793.888119917363` 为同一浮点在两位小数下的显示）。

## 3. 三条结论

1. **修法无副作用**：canonical 协议对**无并列**数据是恒等变换 ⇒ 此前所有面板结果在两种协议下相同，
   历史可比性没有被本次修复破坏。
2. **L8 修法的作用域被确认**：它只在真正出现并列到达时改变行为（第 87 轮的 burst 冒烟里
   64 个槽位被对齐，utility 从 1793.89 变为 1772.67 ⇒ 有并列时确实改变结果）。
3. **开关可以安全地默认打开**：既然无并列时恒等，将来可以把它设为默认（本轮仍保持默认关闭，
   以避免任何未预期的环境差异）。

## 4. 这不能证明什么

- 单日（day 0）；但"逐位相同"是**确定性**性质，不需要多天统计；
- 不证明其它路径（快照、oracle hook、温控推进）也没有顺序依赖——本检验只覆盖决策路径；
- 不证明 burst 数据上的结果正确：那是另一个问题（A-v1+burst 上的 L8 重放仍未做）。
