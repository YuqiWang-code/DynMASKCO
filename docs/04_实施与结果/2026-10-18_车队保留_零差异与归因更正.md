# 车队保留（dispatch-only）两次冒烟：与控制臂**逐位相同** ⇒ 单纯"压住不发车"= 0

- 日期：2026-10-18（继续迭代，第 98 轮）
- 类型：**实验（1 天冒烟 ×2）+ 归因更正**
- 代码：`scripts/admission/panel_replanner.py::FleetReserveReplanner`（新臂 `reserve`）
- 产物：`smoke_reserve`（reserve=1, release=12 h）、`smoke_reserve3`（reserve=3, release=14 h）

## 1. 做了什么

依据 [攒批发车首日记录](2026-10-18_攒批发车_首日.md) 的解释（"增益来自留住 idle 车给后面的高价单"），
把同一思想写成**与到达无关**的形式：在 `release_clock` 之前，除 `reserve` 辆保留车外，
其余 idle 车的 `mutable_suffix` 一律清空（= 不出发）。

两次冒烟：

| 配置 | utility | 收入 | 里程 | 服务单 | feasible |
|---|---:|---:|---:|---:|---|
| reserve=1 / release=12h | **1793.89** | 1840.0 | 461.12 | 94 | True |
| reserve=3 / release=14h | **1793.89** | 1840.0 | 461.12 | 94 | True |
| 控制臂（参照） | 1793.888119917363 | 1840.0 | 461.1188 | 94 | True |

**两次都与控制臂逐位相同。**

## 2. 这暴露了我此前一处**归因错误**（必须更正）

`BatchedDispatchReplanner` 我写的是 `class BatchedDispatchReplanner(StaticPriceReplanner)` ——
它**同时**做了两件事：

1. **接单过滤**（继承静态价，等价于静态 λ 臂）；
2. **派车时机**（pending≥K 或 wait≥W 才放行）。

因此它相对控制臂的 +1.16%（10 天）**不是**"派车时机的功劳"，而是
"静态价过滤（+1.07%）+ 派车时机的边际贡献（约 +1.79 绝对值）"。

而本次 `FleetReserveReplanner` 继承的是 `SaaReplanner`（**没有过滤**），
所以它 = 控制臂 + 纯派车压制 ⇒ 逐位相同 ⇒ **纯派车压制的边际贡献 = 0**。

⇒ 正确表述：
> 攒批发车相对**静态 λ** 的增量是 +1.79（10 天、无并列）与 +9.76（5 天、留出），
> 这**才是**派车时机的贡献；相对**控制臂**的 +1.16% 主要来自它自带的静态价过滤。

这与第 93 轮十日报表的结论一致（batch 与 static 的差距远小于各自与控制臂的差距）。

## 3. 为什么"压住不发车"是零

两个可能，本记录无法区分，但都指向同一结论：

- **SAA 每个事件都重规划**：我把 suffix 清空，下一个事件它照样会派车，
  只是推迟了一个事件；事件间隔由订单到达驱动，一个事件的延迟通常不改变可行集合；
- **保留车辆不是瓶颈**：控制臂的约束是能耗预算与时间窗，不是"车不够"。
  把车留住并不产生新的可服务订单。

⇒ 若要真的改变派车结构，必须改**规划器本身**（与 [记账耦合结论](2026-10-18_跨车重分配_BLOCKED_记账耦合结论.md) 一致），
而不是在 `plan()` 外面做抑制。

## 4. 这不能证明什么

- 只测了 1 天、两个参数点（reserve=1/3，release=12/14 h）；更大范围未扫；
- 不证明"派车时机"整体无效：`batch` 相对静态 λ 仍有 +1.79 / +9.76 的边际证据；
- 不改变任何既有排行榜数字（本臂与控制等价，不入榜）。
