# 里程三条线索同日结果：GPU 构造器 −8.03%；加深 LS = 0；PyVRP 把关 = 0

- 上游：[G4 十日确认](2026-10-18_G4十日确认_NOT_MET.md)（缺口 = 同收入下再省 22.1 km）、
  [里程余量审计 BLOCKED](2026-10-18_里程余量审计_BLOCKED.md)、[PyVRP 适配器冒烟 1](2026-10-18_PyVRP适配器_冒烟1.md)

## 一、GPU：学到的 3 参数打分器把构造里程降 **8.03%**（5 天，一致性很好）

`scripts/bench/gpu_route_batch.py`，R1_CAL day0–4，ρ=3.0 下的接收集合，15 车/容量 50：

| 天 | NN（km） | ES（km） | 增益 |
|---|---:|---:|---:|
| 0 | 277.44 | 260.95 | −5.94% |
| 1 | 285.40 | 252.54 | −11.51% |
| 2 | 297.14 | 280.51 | −5.60% |
| 3 | 295.63 | 264.57 | −10.51% |
| 4 | 285.24 | 266.59 | −6.54% |
| **均值** | **14.41 units** | **13.25 units** | **−8.03%** |

学到的权重（距离/时间窗裕度/载重）：`[1.296,−0.018,0.488] / [0.914,−0.027,0.363] /
[1.231,−0.055,0.574] / [1.115,0.017,0.157] / [1.681,0.004,−0.203]` —— **距离项恒为正且最大（0.9–1.7）**，
负荷项次之且符号不稳，时间窗裕度项几乎为 0。即：**"尽量走近的、适当照顾载重"** 是学到的规则，
5 天里方向一致。

GPU 证据：`nvidia-smi --query-compute-apps` 出现 `4119169, MASKCO_env/bin/python, 24614 MiB`（cuda:0）+ 508 MiB（cuda:1）。

**边界（关键）**：这是**松弛模型**（每车 clock 从零起、不建模 reveal 顺序与派车时机、2-opt 口径不查时间窗），
其 277–297 km 与闭环的 493–522 km **不可比**。它证明的是"构造器本身还有 ~8% 空间"，不是"闭环能省 8%"。

## 二、CPU：加深局部搜索（2 → 6 passes）= **0 差异**

`DeeperLSReplanner` 只覆写 `_local_search_u` 的 pass 数，**不改任何接单规则**：

```
[arm] day 0 ok DeeperLSReplanner utility=1793.89 394.5s
控制臂 day 0             utility=1793.89
```

逐位相同（15 位小数）。含义明确：

**冻结实现里局部搜索在 2 个 pass 内已收敛**，路线质量**不受 LS 深度限制**。
这是一个干净的负结果：想靠"更彻底的局部搜索"省下那 22.1 km 是**走不通**的。

## 三、CPU：PyVRP 可行性把关 = **0 拒绝**（仍逐位等于控制）

参数 `--pyvrp-max-orders 200 --pyvrp-time-limit 0.3`（上一轮已修掉池子上限短路与 `served_mask` 误用）：

```
[arm] day 0 ok PyVrpFeasibilityReplanner utility=1793.89 456.7s
```

仍是逐位相同 ⇒ **PyVRP 从未拒绝任何订单**。

两种可能，**尚未区分**（下一轮要测）：

1. **池子本来就小**：SAA 派车及时，待派车订单常年只有个位数 ⇒ 外部求解器"无事可做"，
   把关天然恒真。若成立，结论是：**在 SAA 架构下，外部求解器把关这个位置是空的**。
2. 判定逻辑仍有 bug（例如池子只含候选单，永远可行）。

我倾向于 1，但**必须实测**（记录池子大小分布）才能写结论。

## 四、三条结果合起来说的话

| 线索 | 结果 | 对 G4 的含义 |
|---|---|---|
| GPU 构造器（松弛） | **−8.03%** | 构造规则本身有余量，但口径不可比 |
| 加深 LS（闭环） | **0** | 局部搜索深度**不是**瓶颈 |
| 外部求解器把关（闭环） | **0 拒绝** | 把关位置可能是空的（待验证） |

⇒ 闭环里程的 22.1 km **不在**"更深的局部搜索"里，也**可能不在**"外部求解器把关"里。
余量更可能在**派车/承诺时机**（构造器的 8% 恰恰来自"重新组织路线"，而那是派车时刻的自由度）。

## 五、这不能证明什么

- GPU 的 −8.03% **不能**换算成闭环效用（松弛口径）。
- 加深 LS 的 0 差异只对**冻结的 `_local_search_u` 实现**成立，不排除换一种邻域会更好。
- PyVRP 的 0 拒绝**不能**说"外部基线不如规则"——它甚至还没真正参与决策。
- 全部为 1 天（两个 CPU 臂）或 5 天（GPU 松弛）单集单种子。
