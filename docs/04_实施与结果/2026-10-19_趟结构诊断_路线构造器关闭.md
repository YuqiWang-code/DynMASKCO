## 1. 为什么先做这道诊断（G4 唯一未否掉的方向需要先过"结构闸门"）

总纲 §11.1 里 G4 唯一还没被否掉的方向是**路线构造器**。在写任何代码之前必须先回答：
"一趟里有几单？车用了几辆？"——如果闭环已经是"一单一趟、15 车全用、里程由半径决定"，
那么"拼趟"就是最大的杠杆；反过来如果闭环已经是"满载长链"，那么杠杆在别处（或根本没有）。

## 3. 三个结构性事实（都可在代码里复核）

### 3.1 三个温区对任何出车车辆**恒为开**，所以"同温区拼趟"在这个模型里**不可能省能耗**

`strict_online_env.py::_coldchain_active_mask()`：

```python
def _coldchain_active_mask(self):
    if self.coldchain_contract is None:
        return ()
    return (True,) * len(self.coldchain_contract.thermal.supported_temp_classes)
```

所有 `transition_segment` 调用都传这个 mask ⇒ 一旦车辆被 `_dispatch_coldchain` 派出，
**18/4/−18 °C 三个温区的待机制冷同时计费**，与车上装了什么无关。
因此"按温区拆趟/单温区车"这条在真实冷链里通常成立的省能机制，**在本评测器里收益恒为 0**；
这也从结构上解释了 `class_tier` 五个变体为什么全是"省但不赚"（它们只砍 `e_lower`，砍不到待机开销）。

### 3.2 固定开销与"车在路上的时间 × 开着的温区数"同向，与装了哪种货无关

能耗三分显示 overhead ≈ **224 kWh/日 = 预算的 32%**（见上引记录）。结合 §3.1（温区恒开）：
overhead 只可能随"出车车辆数 × 在途时长"增长，**与车上装哪种温区的货无关**。
逐趟明细也印证：control day0 四趟段能耗 237.6/230.7/209.6/53.1 kWh，而四趟 `e_lower` 估计只有
~116/116/112/32 kWh ⇒ **单趟能耗里一半以上不是接单口径的预冷能耗**，且与"这趟装了几个温区"无关
（全是混温区趟）。⇒ 想让 overhead 降下来只能压缩**总在途里程/时长**，也就是说
**overhead 与里程同向：省里程会顺带省预算**。

> 未做：本记录没有把 overhead 进一步分解成"在途制冷 / 回仓 / 待机 / 门件预冷"四项
> （现有 dump 只有 `segment_energy_kwh`，不含待机段的分项归因），所以"overhead ∝ 车时"仍只是
> **与两点事实一致的假设**，不是实测比例。

### 3.3 容量把每趟锁在 ~24 单，车队规模不是瓶颈

`capacity = 50`（共享车厢），日均单量 ≈ 2 单位 ⇒ 每年趟约 24–25 单就满载回仓。
服务 94 单只需要 4 辆车 ⇒ **15 车里 11 辆整天闲置**。这与 `FleetReserveReplanner`（保留车队）
**逐位零差异**一致：车队预留做不出任何事，因为车队本来就不紧。

## 4. 对"路线构造器"这条方向的裁决（诚实版）

| 可能动作 | 现状 | 依据 |
|---|---|---|
| 减少趟数（拼趟） | **已到极限**：4 趟已覆盖 94 单，每趟满载 | 本记录 §2/§3.3 |
| 路线内顺序（2-opt / 加深 LS） | **已测死**：与控制在 15 位小数上相同 | `2026-10-18_跨车重分配_BLOCKED_记账耦合结论.md`、`--ls-passes 6` |
| 车辆-订单分配（换车/换趟） | **BLOCKED（结构）**：外部后处理破坏能耗/承诺/去重记账 | OR-Tools 臂能耗 1186.8/710.65；自研重分配 `duplicate_service` |
| 缩短长链几何（换种子/换构造器） | **未被否掉，但没有可用的注入点**：链是"承诺后立即出发"的产物，改它等于重写规划器 | 本记录 §3 + 同引 |

⇒ **结论：G4 剩下的 0.34pp 不能指望"路线构造器"补齐。**
在本评测器语义下，路线层能动的三个旋钮（趟数、顺序、分配）分别处于"已满/已为零/结构阻塞"。
这条方向应当记为 **`ROUTE_CONSTRUCTOR_CLOSED_BY_STRUCTURE`**，而不是继续投算力。

## 5. 这不能证明什么

1. **不能证明"里程不能降"**：只证明"在当前规划器语义 + 当前容量/车数下，三个路线旋钮都动不了"。
   若允许改规划器（重写承诺时机 / 允许跨车搬单），3.47× 的余量仍在理论上存在——但那已经不是基线改进，
   而是"新规划器"，且历史上两次尝试都卡在同一处记账耦合。
2. **不能证明同温区拼趟在真实冷链里无益**：只在**本评测器**（`_coldchain_active_mask` 恒 True）里无益。
   这是模型的一个**建模选择**，若要研究该机制，必须先改评测器契约——那属于协议变更，会作废全部历史面板。
3. **只有 2 天 × 2 臂**（control/batch 各 day 0–1）已读；更长的日序未跑，若与这些结论冲突会追加更正。
   逐趟明细已入库（`trips[]` / `by_composition`），任何复核者可直接重算单/趟、能耗/单。
4. 不主张任何 SOTA / 机制贡献 / G4 达成。
