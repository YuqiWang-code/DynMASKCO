# 预登记：PANEL-OKP（在线背包指数阈值 = OCRS 族的确定性等价物）

- 日期：2026-10-18
- 类型：**预登记**（正式面板实验）
- 上游：总纲 §4.2（I-2 的 OCRS 半边）、[阶段 1](2026-10-18_阶段1执行记录.md)、[PF-1](2026-10-18_PF1_价格场执行记录.md)、[D4 v3](2026-10-18_D4v3_因果DP.md)

## 1. 起因：ICRS 在本协议里能不能成立，先要问协议允许什么

总纲 §4.2 要求"把接拒从逐单阈值升级为联合资源乘子场 + **集合级 contention resolution**"。动手前先核对了冻结协议的可表达性：

`StrictOnlineEnv` 在**每个订单的 reveal 时刻**调用 `replanner._saa_decide(...)`，接受即承诺、拒绝即终局
（`scripts/admission/panel_replanner.py` 的过滤器语义；`scripts/evaluation/scenario_saa.py:415` 的派车规则）。
⇒ **"把一批订单攒起来联合决定接受集合"在冻结协议里不可表达**，除非修改协议本身（那会破坏与既有基线的可比性）。

因此本实验跑的是 OCRS 家族中**在逐单不可撤销协议下仍可表达**的那一支：
**在线背包的指数阈值规则**（Zhou–Chakrabarty–Lukose 2008）

```
d_i = revenue_i / e_hat_i
z   = 1 − budget_remaining / B
φ(z) = (L/e)·(U/L)^z
accept ⟺ d_i ≥ φ(z)
```

其中 `[L, U]` 由 `REV` 与 `e_lower` 的**定义域**算出（L = 1.55、U = 9.52，不看任何未来到达），
竞争比 `ln(U/L)+1 ≈ 2.81`。这是**文献保证**，不是本项目定理。

## 2. 假设

H-OKP：指数阈值（随预算消耗上升）在闭环日效用上**不劣于**最优固定价格（静态 λ\*，1828.65），
因为它把"预算该留给谁"写成消耗比例的函数。

**诚实先验**：阈值为 `φ(0)=0.57 → φ(0.5)=1.41 → φ(1)=3.50`，而三类订单的收入密度下界是
`1.55`（−18°C, q=3）⇒ 在 `z ≲ 0.9` 之前几乎全部接受，行为接近"全接"（控制臂 1808.53）。
因此**预测偏向不劣于控制、但难以超过静态 λ**。这个实验的主要价值是给基准补上一条**带保证的基线**（I-3），而不是冲 Gate。

## 3. 设定（冻结）

| 项 | 值 |
|---|---|
| 入口 | `scripts/evaluation/run_admission_panel.py --arms okp` |
| 臂 | `online_knapsack`（`OnlineKnapsackReplanner` + `policies.OnlineKnapsack`） |
| 变体 `x1` | `scale=1.0`（原式）→ `results/admission_panel/stage6_okp_x1` |
| 变体 `x2` | `scale=2.0`（阈值整体加倍，**开发诊断性变体**，用于看灵敏度）→ `results/admission_panel/stage6_okp_x2` |
| `L, U` | `--okp-l 1.55 --okp-u 9.52`（由定义域算出，**不在 GATE 上调**） |
| 天数 / 数据 | 5 天 / GATE |
| 对照 | 阶段 1 `control` 1808.53、`static_price` 1828.65（同配置同种子，不重跑） |

## 4. 判据（先冻结）

| 判定 | 条件 |
|---|---|
| `OKP-LEAD` | Δ(x1 − 静态 λ) > 0 **且** ≥4/5 天相对控制为正 |
| `OKP-PARITY` | Δ(x1 − 控制) > 0 但 Δ(x1 − 静态 λ) ≤ 0 |
| `OKP-LOSE` | Δ(x1 − 控制) ≤ 0 |

`x2` 只作灵敏度报告，不参与判定（它是为了知道"阈值翻倍会不会更好"，属开发诊断）。

## 5. 这不能证明什么（预写）

- 竞争比是**最坏情形**界；在本实例分布上它可能远松于实际最优，`OKP-LOSE` 不等于"这条规则没有理论价值"。
- 它**不是**集合级 contention resolution。真正的 OCRS（联合决定接受集合）在冻结协议里不可表达；
  要说 OCRS 无效，必须先给协议加"可延迟承诺"再重测——那是协议变更，不是本实验。
- 5 天单集单种子。
- 即使 `OKP-LEAD`，它也是**基线**：规则简单到必然被 depth-3 树反演门判 `RULE_CAPTURABLE`。
