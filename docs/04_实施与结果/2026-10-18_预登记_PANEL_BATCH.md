# 预登记：PANEL-BATCH（攒批发车，派车时机机制）

- 日期：2026-10-18
- 类型：**预登记**（正式面板实验）
- ⚠️ **诚实标注：day 0 已观察到**（`smoke_batch` 1819.10，比控制 +25.21）。因此本文件不是"结果前预登记"，
  而是**在 5 天结果出来之前**冻结判据，并对"day 0 已见"这一点显式登记。day 0 的数字**不**计入本预登记的独立性。
- 上游：[决定性发现 3.47×](2026-10-18_里程余量_347倍.md)、[首日冒烟](2026-10-18_攒批发车_首日.md)、
  [G4 十日确认](2026-10-18_G4十日确认_NOT_MET.md)

## 1. 假设

H-BATCH：**把"何时派车"从"来一单派一车"改成"攒够 K 单或最老订单等超过 W 小时才发"，
能在闭环日效用上稳定优于控制臂**（因为 idle 车辆被保留，后续高价单能被接住）。

**不假设**它降低里程：首日冒烟已显示里程反而上升（461 → 509 km），
因此本实验的主指标是 **utility**，里程只作机理报告。

## 2. 设定（冻结）

| 项 | 值 |
|---|---|
| 入口 | `scripts/evaluation/run_admission_panel.py --arms batch` |
| 臂 | `batched_dispatch`（`BatchedDispatchReplanner`，接单仍用登记静态价） |
| 主配置 A | `--batch-k 8 --batch-wait 1.0` → `stage7_batch_k8w1` |

| 对照 | 控制 5 日 1808.53、静态 λ 5 日 1828.65、控制十日 1796.68、静态十日 1815.82 |

## 3. 判据（冻结，只看 5 日；day 0 不计入独立性）

主指标：`mean_delta = mean(utility_batch − utility_control)`，逐日配对，5 天。

| 判定 | 条件 |
|---|---|
| **BATCH-LEAD** | `Δ > 0` **且** `Δ(相对控制) ≥ +1.5%`（≥1823.6）**且** ≥4/5 天为正 **且** `Δ(相对静态 λ) > 0` |
| **BATCH-WEAK** | `Δ > 0` 但未同时满足上面三条 |
| **BATCH-LOSE** | `Δ ≤ 0` |

辅助报告（不参与判定）：里程、收入、服务单数、能耗、逐日序列；
并按 [3.47× 记录](2026-10-18_里程余量_347倍.md) 第 7 条的口径，对 batch 臂的 day0–4 也做 PyVRP 离线重优化，
给出 `saa_km / reopt_km` 比值是否变化。

## 4. 止损

- 若 batch 臂出现 `hard_feasible=False`（鱼类不可售 / 预算越限）⇒ 该日计入分母并显式报告。
- 若 5 天内 ≥2 天 `hard_feasible=False` ⇒ 判 `BATCH-UNSAFE`，机制作废。
- 若 90 分钟无 `panel.json` ⇒ `BLOCKED(infra)`。

## 5. 这不能证明什么（预写）

- 5 天单集单种子，且 day 0 已被观察过 ⇒ **本实验不是干净的盲测**；若判 `BATCH-LEAD`，
  必须再做 **10 天** 复核（其中 day 0–4 已被"污染"，只算 5 个新的一天）。
- 即便 `BATCH-LEAD`，机制解释仍是"保留 idle 车辆给后续高价单"，**不是**"减少里程"；
  而 3.47× 的里程差距仍未解释。
- 该机制极可能被 depth-3 树反演门判为 `RULE_CAPTURABLE`（规则只有两个阈值），
  那就意味着它是**基线**而不是创新点——按总纲 §1.2 必须照判。
- 不主张任何论文级结论。
