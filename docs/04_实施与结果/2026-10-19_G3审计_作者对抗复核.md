## 3. 发现（1 处已修复 + 3 条边界说明）

### AUDIT-1（**已修复**，严重度 MEDIUM-对产物 / LOW-对主张）

**现象**：`--q-low 6` 时脚本**退出码 0 并输出证书**，而该证书的
`honesty.no_information_price` 写入了**假命题**：

> "在本证书参数下 d_H=**2.326 < 1.587**=d_L，任何常数 ρ>d_L 会把 H 一起拒掉"

`2.326 < 1.587` 是**假的不等式**；且当 `d_H > d_L` 时，取 `ρ ∈ (d_L, d_H)` 会**拒绝 L、接受 H**，
"把 H 一起拒掉"的推论也**反了**。

**根因**：v1（`hard_family.py`）本来有 `d_H < d_L` 的前提守卫，v3 重写时**丢失**；
而 `honesty` 那段的措辞依赖该前提。

**修复**：在 `_guards` 末尾恢复该守卫（3 行 + 注释），触发即 `INVALID_PREMISE` 非零退出。

**修复后验证**：
* `--q-low 6` → `INVALID_PREMISE: 需要 d_H < d_L（当前 d_H=2.325581 ≥ d_L=1.587302）`，退出码 1；
* 默认参数输出**逐字不变**，且新生成的证书与入库
  `certificates/hard_C_pair.json` **逐字段完全相同**（`identical: True`）；
* 9 条守卫测试仍 `ALL_PASS`。

**影响评估（诚实版）**：**默认证书的四项数值主张完全不受影响**（它们只依赖 `r_L/r_H`）；
缺陷只影响"用非默认参数生成证书时的文字正确性"，属于**产物完整性**问题。

### NOTE-1（不可执行的前提：因果性靠论证，不靠代码）

证书的核心论证是"两实例在阶段 1 观测**相同** ⇒ 任何因果策略必须做同一决策"。
这一条是**文字论证**，脚本里**没有**任何代码去检查"观测相同"。
⇒ 审计只能确认它与 v3 的模型定义一致（阶段 1 只有 L），**不能**说它是机器验证的。
这是本证书**固有**的边界，已在 `honesty.scope` 中部分披露，本次再明确一次。

### NOTE-2（`OBJECTIVE` 是本地副本，今天不漂移）

脚本第 45–46 行把 `OBJECTIVE` 写成**本地副本**（理由：panel 侧没有 import 出口）。
本轮实测 `hard_family_c2.OBJECTIVE == run_admission_panel.OBJECTIVE`（**相等**）。
**风险**：若哪天部署侧改了 `ambient_c`/`target_c`/`k`，这份副本会**静默过期**。
建议（未实施，因会动被审脚本的 import 面）：在证书里加一行 `objective_source_sha256`，
或把 `OBJECTIVE` 提到一个共享模块。

### NOTE-3（随机化口径是"期望比值 + oblivious 对手"）

证书给的是 `max_p min(E[·]/OPT)`；**逐实现**的比值在实例 A 上可以为 0。
这一点已写在 `honesty.randomized_convention`，本轮复核确认措辞与实现一致，无夸大。
