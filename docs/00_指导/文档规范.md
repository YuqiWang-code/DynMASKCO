# 文档规范（写什么、写哪里、怎么命名）

> 目的：让 200+ 篇文档仍然可检索、可追溯，且**不产生第二份正文**。
> 与 `C-VRP_Cold-chainVehicleRoutingProblem/00_项目导航.md` 的“放置规则”一致；冲突时以那份导航为准。

## 1. 文档分层

| 层 | 位置 | 回答的问题 | 谁维护 |
|---|---|---|---|
| **入口层** | `README.md`、`docs/`（本目录） | 这是什么、从哪开始、按什么顺序读 | 随手更新 |
| **状态层** | `C-VRP.../项目当前状态.md`、`docs/当前规划/结果与进度/执行进度表.md` | 现在到哪一步、下一个 Gate 是什么 | 每轮结束追加 |
| **方法层** | `C-VRP.../docs/当前规划/{研究设计,工程实现,实验与评估}/` | 方法是什么、怎么实现、怎么评估 | 协议更新时改 |
| **证据层** | `C-VRP.../docs/当前规划/{决策与审计,结果与进度}/`、`research/`、`results/` | 这一次跑出了什么、判据是什么 | **只追加** |
| **历史层** | `docs/当前规划/{历史已收束,历史快照}/`、`archive/` | 为什么当年停在这里 | 不修改 |

## 2. 放哪里（按问题类型选，不要按“我觉得合适”）

| 你要写 | 放这里 |
|---|---|
| 单方向的方案 / 实验记录 | `C-VRP.../{01_取货线,02_配送线,03_负结果线}/文档/` |
| 跨方向的计划、总路线图、阶段裁决 | `C-VRP.../docs/当前规划/决策与审计/` |
| 结果与进度（含 Gate 判定） | `C-VRP.../docs/当前规划/结果与进度/` |
| 方法 / 协议 / 评估口径 | `C-VRP.../docs/当前规划/{研究设计,工程实现,实验与评估}/` |
| 机制诊断 / 负结果 | `C-VRP.../03_负结果线/` 与 `negative_result_paper/` |
| 调研（对比方法、文献清单） | `C-VRP.../docs/当前规划/文献调研/`、`C-VRP.../docs/论文参考/*.md`、`CC_Compare/docs/` |
| 论文 PDF | `C-VRP.../docs/论文参考/<分类>/` + 在 `docs/02_参考文献/README.md` 登记 |
| 接手须知 / 环境 / 规范 | `docs/00_指导/`（本目录） |
| 索引与导航 | `docs/README.md` 与各分类 `README.md` |

**禁止**：把证据层文档复制进 `docs/`、把 `research/` 或 `results/` 里的工件搬到别处（路径与哈希已登记）、在根目录再建一份 `README_2.md` 之类的第二正文。

## 3. 命名

- 计划/审计类：`<主题>_<动作>_<YYYY-MM-DD>.md`，例：`方向A_S3裁决复核与MaskCO主线推进_2026-09-29.md`。
- 阶段协议：`<编号>_<阶段>_<协议名>_<YYYY-MM-DD>.md`，例：`A-v1步骤3锁定协议_MaskCO场景生成器_2026-09-25.md`。
- 索引类：固定名 `README.md`（每层一个）。
- 运行目录：`results/<登记名>/`，登记名不得复用；不得覆盖旧运行目录。

## 4. 每篇“结果类”文档必须自带的最小字段

```text
日期 / 阶段编号 / 一句话结论（PASS|FAIL|BLOCKED|NO-GO）
身份：HEAD commit、compute/control/analysis 哈希、data_sha256、profile/contract 哈希
分母：预期 vs 实际（异常/超时/未尝试分别计数，不得先删后裁）
判据：事前登记的判据原文（不是事后解释）
数字口径：candidate / accepted / closed_loop 三列分列
预算：墙钟/调用次数/显存上限 + 实测
未主张：明确写出“本条不证明什么”
```

## 5. 三列与两个成本（引用数字前必查）

| 列 | 含义 | 易错点 |
|---|---|---|
| `candidate` | 候选解质量（失败回退 J0） | **不得**称“部署质量” |
| `accepted` | 在线接受规则 `min(J0, J)` 之后 | 与 candidate 混用是最常见错误 |
| `closed_loop` | 终局闭环 ΔJ | 需要完整轨迹与 C0 认证 |

`distance_cost` 恒为**纯行驶距离**；冷链复合目标另记 `coldchain_cost`（距离/品质/能耗加权）。硬不可行**不**并入任一标量。

## 6. 失败与勘误

- `FAIL` / `BLOCKED` / `NO-GO` → **只追加**新记录（新版本、新登记、新身份），不得把旧行改成 PASS。
- 发现预声明有错 → 写“勘误条目”（ERRATA），写清**改得更严还是更松**（更松必须显式披露）。
- 已消费的一次性执行机会（如正式比较、最终测试种子）**不重跑、不补跑**；如需再跑，是新登记、新身份。

## 7. 提交

- 每完成一件独立工作就提交并推送（约定见 `README.md` §Git 交付约定；入口 `tools/git_deliver.py`）。
- 提交前跑 `python tools/git_deliver.py --check-only`；行尾与字节容器问题见该工具说明（`core.autocrlf` 必须为 false，本副本已设置）。
