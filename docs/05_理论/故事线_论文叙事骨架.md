# 故事线（论文叙事骨架）：严格在线冷链路由的"信息价格"与"阈值天花板"

- 日期：2026-10-18
- 状态：**叙事骨架**（每一句都对应本仓库已入库的证据；未测的地方明确标"未测"）
- 用途：写作时的章节骨架；同时是"故事性"这一维度的自检清单

---

## 第一幕 · 问题为什么难（不是"没调好"，而是结构性的）

冷链在线路由里，"在线"有三种互不相同的语义，文献常混用：弱在线（滚动时域）、预测增强、严格在线。
本文把**严格在线**写死成可执行协议：订单只在 `reveal_time` 时刻可见，**接受即承诺、拒绝即终局**
（`StrictOnlineEnv`，逐单调用 `_saa_decide`）。

在这个语义下有两条硬结构：

1. **无有限竞争比**：若订单只在自己时间窗起点揭示，对手可以让"低价值先到、高价值后到"
   （构造 B，机制与 Chawla–Christou 2024 同型；本项目的**实例级**论证在
   [G3-b 勘误](../04_实施与结果/2026-10-18_G3b_构造B表述勘误.md) 中两次自否，**不主张**新定理）；
2. **制冷预算使错误不可撤销**：接受一个低密度订单会永久占掉预算，
   高密度订单随后不可服务 —— 这是**精确可算**的
   （[构造 C 证书](../04_实施与结果/2026-10-18_G3a_构造C精确证书.md)：`ALG/OPT ≤ 1/3`）。

> 一句话：**这不是一个"更好的启发式"能解决的问题，信息结构本身就限定了上限。**

## 第二幕 · 我们把问题重新定义为三个可测量的量

`L_future = (OPT_cl − OPT_causal)/OPT_cl`，`L_rule = (OPT_causal − Rule)/OPT_causal`。

在 GATE 集 5 天、接拒层净价值口径下实测（[D4 v1](../04_实施与结果/2026-10-18_D4v1_信息价格分解.md)）：

| 量 | 值 |
|---|---:|
| `OPT_cl`（预知连续） | 2421.07 |
| `OPT_int`（预知整数） | 2419.54 |
| `OPT_price*`（最优固定密度阈值 ρ=2.25） | 2365.42 |
| `Rule`（登记静态影子价格） | 2340.05 |
| **`L_future`** | **2.31%** |
| **`L_rule`** | **0.99%** |
| Rule / `OPT_price*` | **0.990** |

> 一句话：**登记规则已经吃掉最优固定阈值的 99.0%，而全部"未来信息"只值 2.31%。**

## 第三幕 · 于是我们系统地杀死了"更聪明的阈值"

这是本文最实在的部分：不是宣布一个方法，而是**把一整族机制逐个测死**，并给出为什么。

| 机制 | 结果 | 证据 |
|---|---|---|
| 温区/空间/时间价格场（12 参数） | **+0.00% / −0.12% / 斜率 0** | [PF-1](../04_实施与结果/2026-10-18_PF1_价格场执行记录.md) |
| BwK 动态对偶 λ_t | **−1.42%**（5 天） | [阶段 1](../04_实施与结果/2026-10-18_阶段1执行记录.md) |
| 状态依赖 DP 阈值 | 表级 **+1.45%**（5/5 天）→ 全仿真 **−3.50%**（1/5 天） | [D4 v3](../04_实施与结果/2026-10-18_D4v3_因果DP.md)、[PANEL-DP](../04_实施与结果/2026-10-18_PANEL-DP_执行记录.md) |
| 温区收入分层（5 变体，两种排序极性） | **−8% ~ −70%** | [PANEL-TIER](../04_实施与结果/2026-10-18_PANEL_TIER_执行记录.md) |
| OCRS（在线背包指数阈值） | **−24.6%**（0/5 天） | [PANEL-OKP](../04_实施与结果/2026-10-18_PANEL_OKP_执行记录.md) |
| 保形密度阈值（两 α） | **−23.5% / +0.33%**，判 `CONF-EQUIVALENT` | [PANEL-CONF](../04_实施与结果/2026-10-18_PANEL_CONF_执行记录.md) |
| 万天级 GPU 复核：分时段阈值 | **+0.27% / +0.48% / +0.25%**（R1/R3/R1c，4200 天） | [GPU 批量接拒层](../04_实施与结果/2026-10-18_GPU批量接拒层.md) |

三条可写进论文的判据性结论：

1. **DP 的符号翻转**：表级 +1.45% → 全仿真 −3.50%。它学的是"预算分配"，真瓶颈是"可行性分配"。
2. **品质项数值惰性**：`quality_weight` 1.0→0.0 轨迹**逐位相同**（Δ=0.00 精确零）——
   此前"冷链感知影子价格"实际只有"收入 vs 预冷能耗"在起作用。
3. **失败模式一致**：输得最惨的臂都是"排除某一类订单"的臂，它们**里程很短、收入很低**
   （`tier0`：365.5 km / 586 收入；`okp`：433.0 km / 1408 收入）⇒ **优化了"省"而不是"赚"**。

> 一句话：**在严格在线 + 冻结评测口径下，三类"更聪明的阈值"（场 / 在线背包 / 保形）都没有超过一个调好的常数阈值。**

## 第四幕 · 那 1.07% 与 G4 门槛之间差的是什么（可算术地回答）

十天面板（[G4 十日确认](../04_实施与结果/2026-10-18_G4十日确认_NOT_MET.md)）：

| 臂 | 收入 | 里程 | utility |
|---|---:|---:|---:|
| 控制 | 1846.0 | 493.2 | 1796.68 |
| 静态 λ | 1868.0 | 521.8 | 1815.82 |

静态 λ 的 +19.14 是"**多接 22 收入、多跑 28.6 km**"的净效果。
要跨 G4（+1.5% ⇒ ≥1823.6），需在同一收入下把里程压到 **≤499.7 km**，即**再省 22.1 km（−4.2%）**。

> 一句话：**缺口不在阈值，在"每单位收入的里程"。**

## 第五幕 · 我们拿得出手的东西（正面结构，而不是"我们失败了"）

1. **协议**：[Strict-Online Protocol](../05_理论/协议_StrictOnline_ColdChain_DVRP.md) + 四条基准设计原则
   （承诺不可撤销 / 可表达性须声明 / oracle 定义域须含约束 / 结论须由数值生成），
   其中第三条来自我们自己踩过的坑，第四条来自我们两次自否。
2. **基准**：CC-DVRP-3T，三 regime × 30 天 + GATE 5 天，18000 单，**5 项泄漏检查 0 失败**，
   且已定位两处**自身**泄漏/薄弱点（L6 预算自标定、L8 并列到达缺失）并给出修法。
3. **可复核上界**：构造 C 的 `ALG/OPT ≤ 1/3`（实例级，附证书 JSON）。
4. **完整负结果表**：[闭环排行榜](../04_实施与结果/2026-10-18_闭环排行榜_GATE.md) 15 臂，
   同一协议、同一数据、同一种子。

> 一句话：**我们交付的是一个"能证否自己"的基准 + 一份把机制族逐个测死的实验记录 + 一条明确指向余量的算术。**

## 第七幕（2026-10-18 续，第 81–92 轮）：三条补强 + 一条新的负面结构

### 7.1 G3 变成**可写进附录的引理**（经三轮独立复核）

构造 C 从"单实例枚举"被两次否决后，改为**实例对**（A={L}、C={L 然后 H}，阶段 1 观测相同）：

- **确定性**因果策略：最坏情形比值 ≤ **1/3**（接 L 的策略取等号）；
- **随机化**因果策略（min-of-expectations）：≤ **3/5**（以 3/5 概率接 L 取等号）；
- 常数密度阈值子族：至多 1/3。

第三轮复核结论："**可接受为附录引理**（在所述范围内）"，并给出定稿措辞。
关键边界：**不是**竞争比定理、**不是** CC-DVRP-3T 的界、**不是**信息价格（实例 C 上信息价格为 **0**，
见证是"永远拒绝 18 °C 类别"这条因果规则，**不是**常数 ρ>d_L——后者会把 H 一起拒掉）。

### 7.2 "外部强基线进不来"有了**结构性解释**（两次实测）

| 尝试 | 结果 |
|---|---|
| OR-Tools 作**路线求解器** | utility 2339 但能耗 **1186.8 / 710.65**，四条失败标签（预算/承诺/服务一致性） |
| 自研**跨车重新分配** | utility 137、服务单崩到 7，`budget_violation` + `duplicate_service` |
| 同集合 **2-opt**（只重排、不改集合） | 与控制臂**逐位相同**（零差异） |

⇒ **能耗、承诺、去重的记账都写在 `SaaReplanner` 的规划路径里**。
任何"在 SAA 外面优化路线/分配"的尝试都会失去不变量维护者。
**这条是基准论文可以主张的设计事实**：它解释了为什么"外部强基线"必须以
admission-filter 或离线对照的形式进入，而不能以"路线求解器"的形式进入。

### 7.3 Gate 判定对 **regime** 高度敏感（同一规则，两种结论）

| regime | 控制 | 静态 λ | Δ | 正日 | G4 口径 |
|---|---:|---:|---:|---:|---|
| 无并列 | 1796.68（10 日） | 1815.82 | +1.07% | 6/10 | **NOT MET** |
| **burst 0.30** | 1777.92 | **1812.16** | **+1.93%** | **8/10** | **MET** |

**同一个常数阈值规则**，只因为把一部分 `reveal_time` 对齐到 0.25 h 网格，就从"不达标"变成"达标"。
⇒ 论文里 **Gate 的定义必须连同 regime 一起写**；否则数字可以被 regime 选择操纵。
这是我们作为基准论文的**方法学观察**，也是自我审查的一条红线。

### 7.4 攒批发车从"参数运气"升级为"**稳健的强基线**"

预登记的留出稳健性检验（day 10–14，该集此前只跑过 W=1.0）：

| W | 留出均值 | 对静态 λ |
|---|---:|---:|
| 0.75 | 1824.09 | +7.03 |
| 1.0 | 1826.84 | +9.78 |
| 1.5 | 1818.63 | +1.57 |

三者相差 ≤8.2 且**都高于静态 λ** ⇒ 判 `W-ROBUST`。
但它仍是 `RULE_CAPTURABLE`（反演门）⇒ **强基线，不是创新点**。这两条要一起写。

### 7.5 这一幕对"故事"的净影响

- **正面**：G3 有了可发表的引理；基准有了 regime 敏感性的方法学观察；外部基线的不可接入性有了结构解释。
- **负面**：仍然**没有**任何机制在无并列 regime 下超过最强基线（+1.59%、7/10 是最好成绩）。
- 因此故事仍应按 **协议 + 基准 + 负面证据 + 一条可写入附录的引理** 来写，
  而不是方法论文——这与总纲 §4.4 第三支的裁决一致。

## 第八幕（第 96–98 轮）：把"派车时机"的功劳**拆干净**

### 8.1 一处归因错误的更正

`BatchedDispatchReplanner` 同时做了两件事：**接单过滤**（继承静态价）+ **派车时机**（pending≥K 或 wait≥W）。
因此它相对**控制臂**的 +1.16%（10 天）**不能**记在"派车时机"头上。

拆开之后：

| 对照 | 数值 | 含义 |
|---|---:|---|
| 静态 λ vs 控制（10 天） | +1.07% | 纯过滤的贡献 |
| **batch vs 静态 λ（10 天）** | **+1.79 绝对值** | **派车时机的真实边际** |
| batch vs 静态 λ（5 天留出） | +9.76 | 同上，另一数据集 |
| batch vs 静态 λ（burst 0.3，10 天） | −4.68 | **符号翻转**（见第七幕 7.4 / RATE-POINT） |

### 8.2 "纯派车压制"= 0（两次实验）

实现 `FleetReserveReplanner`：`release_clock` 前只允许 `fleet − reserve` 辆车出发（**不含**接单过滤）。

| 配置 | utility | 与服务单 |
|---|---:|---:|
| reserve=1 / release=12 h | 1793.89 | 94 |
| reserve=3 / release=14 h | 1793.89 | 94 |
| 控制臂 | 1793.888119917363 | 94 |

**逐位相同** ⇒ 单纯压住不发车 = 0。

原因（两条都指向同一结论）：SAA **每个事件都重规划**（推迟一个事件通常不改变可行集合）；
且控制臂的瓶颈是**能耗预算 + 时间窗**，不是车辆数。

### 8.3 这个机制族现在有五条独立证据

| 干预方式 | 结果 |
|---|---|
| 加深局部搜索（2→6 pass） | **0** |
| 同集合 2-opt 重优化 | **0** |
| 车队保留（纯派车压制） | **0** |
| 跨车重新分配 | **BLOCKED**（`budget_violation` + `duplicate_service`） |
| OR-Tools 替换路线 | **BLOCKED**（能耗 1186.8 / 710.65，四条失败标签） |

⇒ 一句可写进论文的话：

> **在冻结的严格在线环境里，"路线/分配/发车"这一层的任何外部干预，要么无效（0），要么破坏不变量（BLOCKED）。
> 唯一有效的层是"接单过滤"（+1.07%）；其次是规划器内部的派车时机（相对过滤 +1.79），但它对 regime 敏感、且可被浅树复现。**

### 8.4 这对"故事"的净影响

- 故事的**负面部分更硬了**：现在有五条独立证据说明"外壳式改进"无效或非法；
- 故事的**正面部分不变**：协议 + 基准 + 附录引理（G3）；
- **方法学结论**：真正要动 3.47× 里程余量，只能重写规划器（记账与路线不可分离），
  这是一个明确的工程门槛，而不是一个"再试一个技巧"的空间。
