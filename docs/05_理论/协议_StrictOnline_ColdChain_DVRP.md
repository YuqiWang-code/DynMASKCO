## 1. 这份报告要解决的问题

冷链在线路由的文献里，"在线"有三种互不相同的含义，混用会让实验无法比较：

| 含义 | 特征 | 本文是否允许 |
|---|---|---|
| **弱在线**（rolling horizon） | 每个决策点可以看到未来一段时间窗的订单 | ✗ |
| **预测增强** | 给出未来到达的预测，允许其错误 | ✗（作为独立变量另设臂） |
| **严格在线（strict-online，本文）** | 只能读已揭示订单；接受即承诺、拒绝即终局 | ✓ |

本文贡献 = **把这个语义写死成可执行协议**，并给出泄漏测试、oracle 定义与可表达性边界。

## 2. 协议要素（已实现）

1. **事件流**：`(reveal_time, temp_class, demand, tw_start, tw_end, coords)`；
   `event_stream.jsonl` 逐事件可回放（`scripts/bench/cc_dvrp3t_gen.py`）。
2. **决策时刻**：订单 $i$ 在其 `reveal_time` 处进入，策略必须**立即**给出 accept/reject；
   accept 即占用车辆与制冷能耗预算，reject 为终局（`StrictOnlineEnv`）。
3. **三温区与能耗**：18 / 4 / −18 °C；预冷能耗 $e = 0.15\,q\,|25 - T_c|$；
   日预算 $B$ 内生于该 regime 的 `mean_full_energy`（不是手调常数）。
4. **品质**：Arrhenius 品质（合同 v2），鱼类以**可售**为硬约束；番茄品质为报告量。
5. **目标**：冻结 a1 口径 $U = \text{revenue} - 0.1\cdot\text{distance}$（**只此一条**）；
   `distance_cost` 与 `coldchain_cost` 严格分列，不得互相替代。
6. **四列 oracle**：`OPT_cl`（预知连续）/ `OPT_int`（预知整数）/ `OPT_causal`（因果最优）/ `Rule`。
7. **泄漏检查**：`scripts/bench/verify_no_future.py --strict`，5 项检查；
   六个数据集（R1/R1c/R3 × CAL30/GATE5，共 18000 单）**全部 0 失败**。

## 3. 基准设计原则（本文真正的新增内容）

**原则 1（承诺不可撤销）**：决策必须在 reveal 时刻终局。这保证任何策略都不能"攒一批再决定"。

**原则 2（可表达性必须声明）**：在承诺不可撤销（延迟窗口 $w=0$）下，
**集合级 contention resolution（OCRS）不可表达**——它需要对元素保持"未定"直到批内到齐。
因此任何"OCRS 无效"的结论必须先声明 $w$，否则是把协议限制误读成算法缺陷。
本仓库当前 $w=0$，并**如实**把 OCRS 的实测限制在它的可表达子族（在线背包指数阈值）上。

**原则 3（oracle 定义域必须含约束）**：`OPT` 若忽略容量/能耗，会得到"规则等于最优"的假象。
本项目在构造 B 上正踩过这个坑（把容量 1 的 `OPT` 写成 `max(k·ε,1)`），已勘误入库。

**原则 4（结论必须由数值生成）**：证书与记录里的自然语言结论一律由计算生成，禁止手写。

## 4. 已知边界（审稿人会问）

1. 实例族是**自建**的（无公开冷链在线的直接对标），合法性来自参数内生而非文献标准。
2. 冻结 a1 目标只给收入与距离定价；品质/能耗是约束与报告量。要谈"冷链感知"的增益，
   必须换到给两者定价的目标上（CC-DVRP-3T 正式目标），二者不可混读。
3. 接拒层机制族已被关闭（见 `docs/04_实施与结果/2026-10-18_路线裁决_接拒层关闭.md`）；
   本报告的定位是**协议 + 基准**，不是方法论文。
4. 泄漏检查通过 ≠ 策略因果；还要有 dispatch 侧白名单。
