## 0. 记号

一个营业日 = 事件序列。订单 $i$ 在 $t_i$（`reveal_time`）揭示，带
温区 $c_i \in \{0,1,2\}$（18/4/−18 °C）、需求 $q_i$、时间窗 $[a_i, b_i]$、位置 $x_i$。
车队 $V$ 辆，容量 $Q$，horizon $T$，制冷能耗预算 $B$。

- 预冷能耗（登记口径）：$e_i = \kappa\, q_i\, (T_{\text{amb}} - T_{c_i})$，$\kappa = 0.15$。
- 收入：$r_i = \mathrm{REV}[c_i] = \{10, 20, 30\}$。
- 冻结 a1 效用：$U = \sum_{i \in S} r_i - \beta \sum_{\text{routes}} \text{len}$，$\beta = 0.1$。
- 密度：$d_i = r_i / e_i$。在本实例族上 $d_i \in [1.55, 9.52]$，中位数 3.42。

**信息约束（严格在线）**：$t$ 时刻的决策只能依赖 $\{i : t_i \le t\}$ 与自身历史动作；
不得读 $t_i > t$ 的任何字段、不得读当日真实剩余单数。接受即承诺、拒绝即终局
（`StrictOnlineEnv` 在 reveal 时刻调用 `_saa_decide`）。

**四类 oracle**（总纲 §8.2）：`OPT_cl`（预知全部，连续）、`OPT_int`（预知 + 整数决策）、
`OPT_causal`（因果最优，状态可观测）、`Rule`（登记规则）。

## 1. 分解量

$$
L_{\text{future}} = \frac{\mathrm{OPT_{cl}} - \mathrm{OPT_{causal}}}{\mathrm{OPT_{cl}}},
\qquad
L_{\text{rule}} = \frac{\mathrm{OPT_{causal}} - \mathrm{Rule}}{\mathrm{OPT_{causal}}} .
$$

**实测（GATE 5 天，接拒层净价值口径）**：

| 量 | 值 |
|---|---:|
| `OPT_cl` | 2421.07 |
| `OPT_int` | 2419.54 |
| `OPT_price*`（最优固定密度阈值 ρ=2.25） | 2365.42 |
| `Rule`（登记静态影子价格） | 2340.05 |
| $L_{\text{future}}$ | **2.31%**（整数口径 2.25%） |
| $L_{\text{rule}}$ | **0.99%** |
| Rule / `OPT_price*` | 0.990 |

⇒ **规则已吃掉因果最优的 99.0%**；剩下的 2.31% 是"未来信息"，而登记规则离"最优固定价格"也只差 1.0%。
这直接支撑了 [路线裁决](../04_实施与结果/2026-10-18_路线裁决_接拒层关闭.md) 落 §4.4 第三支。

## 2. 命题 A（规则最优性 · **标准**）

**命题 A.** 单资源（能耗预算 $B$）、i.i.d. 到达、线性能耗、目标 $\sum r_i$ 的在线背包问题，
在"接受即承诺"的在线协议下，其**流体松弛**的最优策略是常数密度阈值

$$
\text{accept} \iff d_i \ge \rho^\star,
\qquad
\rho^\star = \text{使 } \mathbb{E}\Big[\sum_i e_i \mathbf{1}\{d_i \ge \rho\}\Big] = B \text{ 的阈值},
$$

且 $\rho^\star$ 等于该 LP 的能耗对偶价格。

**论证（标准 LP 对偶 + 交换）.** 流体松弛为 $\max \sum_i x_i r_i$ s.t. $\sum_i x_i e_i \le B$, $0\le x_i \le 1$。
其最优解是"按密度从高到低装填"，即 $x_i = 1$ 当 $d_i > \rho^\star$、$=0$ 当 $d_i < \rho^\star$，
其中 $\rho^\star$ 为预算约束的对偶变量。在线侧，任何"装入一个密度低于 $\rho^\star$ 的项"的动作
都可以与其后某个密度更高的项交换而不减少 $\sum r$、且不增加能耗；由于到达 i.i.d.，
"等更密的项"在期望意义上不劣。⇒ 常数阈值在期望目标下最优。∎

**边界（必须写清）**：命题 A **不含**路由耦合（容量、时间窗、派车时机）。
实测确实在这一点上失败：全仿真里最优固定 ρ 只拿到控制臂 $+1.11\%$，而
$L_{\text{future}}$ 的 2.31% 无法靠阈值拿到（[PANEL-TIER](../04_实施与结果/2026-10-18_PANEL_TIER_执行记录.md)、
[PANEL-DP](../04_实施与结果/2026-10-18_PANEL_DP_执行记录.md)）。
命题 A 的价值是**给出接拒层的上界**，从而把研究火力从接拒层移开——这正是本轮裁决的逻辑依据。

## 3. 命题 B（时间窗揭示 ⇒ 无有限竞争比 · **本文的实例族，机制与 Chawla–Christou 同型**）

**构造 B（参数化）.** 一条线上的站点 $0$（depot）与 $1$；两辆车；容量 1；horizon $T$。
订单 $i$ 的窗口为 $[a_i, a_i + \delta]$，且**只在 $a_i$ 时刻揭示**（"窗口起点揭示"）。
对手按如下方式出单：

- 阶段 1：在 $a_1 = 0$ 揭示 $k$ 个 **低价值**订单（$r=\epsilon$，位于站点 1，窗口 $[0,\delta]$）；
- 阶段 2：在 $a_2 = \delta$ 揭示 1 个 **高价值**订单（$r=1$，位于站点 1，窗口 $[\delta, \delta+\delta]$）。

**命题 B.** 对任意因果策略，存在该族的参数使
$\mathrm{ALG} / \mathrm{OPT} \to 0$ 当 $k\to\infty$ 且 $\epsilon \to 0$；
因此**不存在有限竞争比**。

**论证.** 阶段 1 时，任何策略都无法区分"这些 $\epsilon$ 订单之后是否还有 $1$ 订单"。
若策略接受任一 $\epsilon$ 订单，则车辆被占用/派出，阶段 2 的 $1$ 订单不可服务 ⇒ $\mathrm{ALG} \le \epsilon$，$\mathrm{OPT}=1$。
若策略拒绝全部 $\epsilon$ 订单，取 $\epsilon = 1$ 的实例（此时 $k$ 个订单都值得接），则该策略只得 0 而 $\mathrm{OPT}=k$。
取合适的 $(\epsilon, k)$ 使两种失误都致命 ⇒ 比值无界小。∎

**与文献的关系**：Chawla & Christou（*Online Time-Windows TSP with Predictions*, APPROX/RANDOM 2024）
在"无预测"时证明无有限竞争比、有预测时给出关于网络直径的对数竞争比。
本构造是它在**冷链三温区 + 能耗预算**下的实例化，本身**不是**新定理；本项目的增量是把它做成
**可执行的事件流**（`scripts/bench/cc_dvrp3t_gen.py` 的 R3 regime）并给出泄漏检查。

**状态（2026-10-18 勘误）**：本文原先设想的**单实例枚举证书不成立**——容量 1 时中间那段阈值已达 OPT，见 [`G3-b 勘误`](../04_实施与结果/2026-10-18_G3b_构造B表述勘误.md)。命题 B 的正确形式必须是**两实例 / 随机化层面**的下界（Yao 型），那是尚未完成的论证工作；本节其余内容（构造描述、与文献的关系）不变。
这是 G3 的下一步，也是本笔记目前最大的空缺。

## 4. 命题 C（制冷预算 ⇒ 不可撤销插入错误 · **本文**）

**构造 C（参数化）.** 单辆车、容量充足、horizon 长；能耗预算 $B$ 恰好吃不下两单。
阶段 1 揭示订单 $L$：温区 18 °C（$e_L = \kappa q \cdot 7$，$r_L = 10$，$d_L = 4.76$）；
阶段 2 揭示订单 $H$：温区 −18 °C（$e_H = \kappa q \cdot 43$，$r_H = 30$，$d_H = 2.33$）。
令 $B = e_H + \eta$ 且 $\eta < e_L$。

**命题 C.** 任何在阶段 1 接受 $L$ 的因果策略都无法再服务 $H$（能耗已不可逆地占用）；
而 $\mathrm{OPT}$ 拒绝 $L$ 而接 $H$。比值差距为 $\Theta(U/L) = \Theta(d_L / d_H) = 6.1$。

**论证.** 能耗预算在接单时被承诺（预冷不可逆），后续无任何动作能退回 ⇒ 单调性；
$B - e_L = e_H + \eta - e_L < e_H$ ⇒ $H$ 必然越限。∎

**为什么这条重要**：它说明**低密度订单会挤掉高密度订单**，这是接拒层唯一真正"值钱"的结构。
但在本实例族上密度比 $d_L/d_H = 4.76/2.33 = 2.04$（不是 6.1，因为 $r$ 的比例 3 慢于 $e$ 的比例 6.1），
而**实测**三温区服务率已经是 $0.708/0.597/0.312$——即系统已经在做这件事，
这正是 [PANEL-TIER](../04_实施与结果/2026-10-18_PANEL_TIER_执行记录.md) 里"硬性温区排除全负"的原因：
**它已经被做掉了，再做一次只会过度。**
命题 C 因此在本实例族上给出的是**上界而非机会**——这是本轮最重要的理论—实验互证。

## 5. 命题 D（协议可表达性 · **本文，基准设计原则**）

**命题 D.** 在"accept/reject 必须在 reveal 时刻终局"的协议下，
**集合级 contention resolution（OCRS）不可表达**：任何 OCRS 都需要对到达元素保持"未定"状态，
直到一个批次内所有元素到齐后再联合决定。

**推论（对基准设计的要求）.** 要用同一份事件流同时评测"逐单阈值族"与"集合承诺族"，
协议必须提供**可延迟承诺**（例如：承诺窗口 $w$，$t$ 时刻必须对 $t-w$ 之前揭示的订单终局）。
这是一个**基准设计选择**，不是实现细节；本项目的 `StrictOnlineEnv` 目前取 $w=0$（最严），
于是把 OCRS 排除在可比集合之外 —— 这一事实必须写进论文的协议章节，否则"OCRS 无效"会被误读。

**状态**：命题 D 是定义级的观察，不经证明也成立；实验侧的对照是
[PANEL-OKP](../04_实施与结果/2026-10-18_预登记_PANEL_OKP.md)（测的是 OCRS 在 $w=0$ 下的可表达子族）。

## 8. 勘误（2026-10-18，独立复核后）：命题 C 的三处必须更正

独立复核（见 [`G3 独立复核：UNPROVEN`](../04_实施与结果/2026-10-18_G3独立复核_UNPROVEN.md)）指出本节命题 C 存在实质错误，
逐条更正如下。**本节正文保留不改**（便于追溯），以本勘误为准。

### 8.1 "信息价格 = 2/3" **错误**

正文 §3 末写"未来信息的价格 = 1 − 1/3 = 2/3"。**这是范畴错误**：
常数阈值 `ρ > d_L`（例如 ρ=5）或"拒 18°C 类"是**纯因果**的、不含任何未来信息，
在构造 C 上得分正是 **OPT = 30**。因此在构造 C 上：

> **因果最优 = 预知最优 ⇒ 信息价格 = 0。**

2/3 只是"单值常数密度阈值族"在该实例上的亏空，**不是**信息的价格。
正文该句作废。

### 8.2 阈值族必须显式限定为"单值、阶段无关"

正文的"对所有 ρ"只对**单值且不随 clock/状态变化**的阈值成立。
部署侧的 `RegisteredShadowPrice.lambda_for(clock, budget_remaining)` 与
`DynamicPriceCurve.lambda_for_ratio` 都允许价格随时间变化；一个分段规则
（λ(0) > d_L、λ(δ) ≤ d_H）在构造 C 上同样拿到 30 ⇒ 该族**不受** 1/3 约束。

### 8.3 数值：6.1 应为 **2.05**，实例差距是 **3**

正文 §4 写"比值差距为 Θ(U/L) = Θ(d_L/d_H) = 6.1"。正确值：

- 能耗比 `e_H/e_L = 43/7 = 6.14`（**不是**密度比）；
- 密度比 `d_L/d_H = 30/12.9 ÷ 10/2.1 = 2.326 / 4.762` 的倒数 ⇒ **d_L/d_H = 2.05**；
- 该实例上 OPT/最佳阈值 = 30/10 = **3**。

三个数（6.14 / 2.05 / 3）含义不同，正文把它们混用了。

### 8.4 正确的表述形态（若要做成真正的界）

把构造 C 与 `I₂ = {只有 L}` 配成**实例对**（两实例在阶段 1 观测完全相同）：

- 确定性策略：接 L ⇒ 比值 (1/3, 1) ⇒ 最坏 **1/3**；拒 L ⇒ (1, 0) ⇒ 最坏 **0**。⇒ 最坏 **1/3**；
- 随机化策略：以 p 接 L ⇒ `min(p, (p·r_L + (1−p)·r_H)/r_H)`；最优 `p* = r_H/(2r_H − r_L) = 3/5`，值 **3/5**。

⇒ 诚实结论应写作"**确定性 1/3、随机化 3/5**"，而不是"2/3 的信息价格"，
并且必须写成**上确界**（"任何因果策略不超过该值，且该值可达"），**不得**写成"任意策略都等于"。

> 勘误补记（第二份独立复核后）：此前这里写的是"随机化 1/2（p=1/2）"——**那是错的**，
> p=1/2 只给出 1/2，最优在 p=3/5 处取 **3/5**。证书 v3（`scripts/bench/hard_family_c2.py`）
> 用闭式 + 单测断言了这一点（`scripts/tests/test_hard_family_c2.py` 9/9 PASS）。
